# BHOME — Bản đồ đọc code frontend

Tài liệu chỉ đường theo mã đang chạy trên nhánh refactor từ `develop` (mốc `f3be1bfe`). Mục đích: từ thao tác của người dùng tìm được màn hình, hàm gửi request và API backend. Không phải đặc tả nghiệp vụ mới; đọc tài liệu backend tương ứng để biết điều kiện giao dịch, bảng dữ liệu và quy tắc chuyển trạng thái chính xác.

## 1. Bắt đầu đọc ở đâu?

| Ứng dụng                          | Điểm vào và định tuyến                                                                                                                                                | Gọi backend                                                                                                                                                                                                                                              |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Owner Web (`src/owner-web/src`)   | `main.tsx` → `App.tsx` → `app/router.tsx`; `app/routeGuards.tsx` kiểm tra quyền, `components/layout/AppShell.tsx` là khung portal                                     | `hooks/useOwnerWorkspace.ts` (`useOwnerQuery`, `useOwnerAction`); các hook `use*Api` trong từng feature; `features/meters/useMeterApi.ts` → `packages/client-core/src/api.ts` (`createApiClient`); hợp đồng dùng `features/contracts/useContractsApi.ts` |

### Các chốt cần hiểu trước khi sửa

- `app/_layout.tsx` bọc `TenantContractAccessGate` và `TenantProfileGate`. `features/tenant/TenantContractAccessGate.tsx` tìm hợp đồng `Active` qua từng trang `/api/v1/contracts` và dùng `isActiveRoomRental`; không có hợp đồng thuê hiện tại thì giao diện bị giới hạn, chỉ đọc lịch sử hợp đồng. Không suy luận hợp đồng Holding là thuê hiện tại.
- `navigation.ts` và `WorkspaceScreenView.tsx` chặn truy cập UI theo role; `ownerWebOnlyScreens` giữ liên kết cũ đến một số chức năng quản lý nhưng hiện thông báo dùng Owner Web. Quyền cơ sở và quyền đối tượng vẫn do backend kiểm tra.
- Bàn giao: mở task → lưu bản nháp từng phần → gửi kiểm tra → chủ trọ/khách thuê thực hiện bước xác nhận theo trạng thái server. `canStaffEditMoveIn`, `canTenantRespondToMoveIn` trong `services/moveInHandover.ts` quyết định giao diện được phép thao tác. Trả phòng dùng draft riêng; đọc client hợp đồng để tìm gửi đề xuất, chấp nhận, phản hồi và khoản thu/hoàn.
- Điện nước: OCR là gợi ý, thao tác xác nhận gọi backend; hóa đơn và trạng thái thu tiền lấy dữ liệu API. Không đổi trạng thái Paid dựa vào QR, ảnh chụp hay thao tác chuyển khoản ở frontend. Các mutation có `expectedVersion` hoặc idempotency key cần giữ nguyên.
- Preview/mock và các công cụ demo là đường chạy thực tế có điều kiện, không được xóa chỉ vì không nằm trong giao diện live.

Không gọi API ghi hợp đồng hoặc thanh toán từ đây.

## 5. Client-core — phần dùng chung

`packages/client-core/src/` giữ các kiểu dữ liệu, client API và logic giao diện dùng chung. Đọc theo feature thay vì đọc cả package:

| Mục tiêu                          | File chính                                                                                                                                                                                      |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Transport, session, phân quyền    | `api.ts` (`createApiClient`), `config.ts`, `sessionClient.ts`, `jwtSession.ts`, `auth.tsx`, `roles.ts`                                                                                          |
| Hợp đồng, giữ chỗ, ký             | `contracts.ts` (`contractClient`, `contractActions`, `actionPayload`, `mutationKeys`), `mainDrafts.ts`, `signing.ts`, `internalSigning.ts`, `useContractLifecycle.ts`, `useContractHandover.ts` |
| Cơ sở, tài sản, biểu phí          | `propertySetup.ts`, `sharedConfiguration.ts`, `locationSetup.ts`, `assetLifecycle.ts`                                                                                                           |
| Hóa đơn, điện nước, thu/hoàn tiền | `meter.ts`, `invoices.ts`, `billingAutomation.ts`, `payments.ts`, `adjustments.ts`, `refunds.ts`, `mainInitialPayment.ts`                                                                       |
| Tài chính, cư trú, thông báo      | `finance.ts`, `residence.ts`, `notifications.ts`, `localization.ts`                                                                                                                             |

Ví dụ cách truy vết BF-05: `/workspace/meter-reading` → `MeterTasksScreen` → `app/meter.tsx` → `meterService.ts` → `POST /api/v1/capture/meter-tasks/{id}/confirm`. Từ đó tìm action tương ứng trong backend rồi đọc service, DB và test của action đó. Cách này giúp giải thích nghiệp vụ bằng một luồng request xuyên suốt thay vì ghi nhớ mọi file UI.

## 6. Rà soát mã không còn dùng

Đã loại bỏ `IncidentWorkspace.tsx` (bản cũ, thay bằng `IncidentManagementWorkspace` / `IncidentDetailWorkspace` / `UnifiedWorkPage`), ba panel Owner Web không còn được mount (`SignatureImagePanel`, `ViettelSettingsPanel`, `MeterAssignment`) và trang khởi tạo Vite mẫu cùng tài nguyên của nó. Đã kiểm tra tham chiếu import thường/dynamic, test, script và cấu hình trong Git; không xóa API ký, cấu hình Viettel hay phân công công tơ ở backend/client-core. Các tài liệu audit lịch sử vẫn có thể nhắc tên file đã bỏ. `ErrorBoundary.tsx` và `useSmsRecovery.ts` không có consumer nội bộ tìm được, nhưng còn thuộc wildcard export của package client-core nên giữ lại để tránh thay đổi giao diện package khi chưa xác minh consumer ngoài repo. Không xóa route cũ, mock/preview, test hay cấu trúc dữ liệu đang được sử dụng. Build/test do bước kiểm tra tích hợp của nhánh refactor thực hiện.
