# BF01 — Compact Operations Workspace: reference implementation

## Scope and baseline

Phase 0–1 and three reference screens only: Location list, shared room-type template library, and Location overview. BF01 / UC04–07 / FE01, GBR01–03, GBR08–09 and GBR13 remain applicable. Preserve the current blue identity, API contracts, scoped permissions, shared/local RoomDefaults distinction and effective-price/contract invariants. No backend, dependencies, schema, or development database changes.

Baseline: the two Owner-provided JOB09 screenshots and the existing components showed oversized controls, spacing and cards. A new before-screenshot run against the development environment was blocked by HTTP 401 on login with the existing local QA account; the application and HTTPS API health endpoint were reachable. Do not interpret older screenshots or historic E2E runs as fresh regression results. Actual rendering checks use a disposable PostgreSQL database, existing API build and isolated Vite instance with synthetic sample accounts/data.

## Design contract

See `src/owner-web/DESIGN.md` for the shared compact density rules. Headings 24/18px, body 14px, desktop controls 36px, tables 8px × 12px cell padding, tabs 42px, desktop navigation rows 36px. Mobile controls retain larger touch targets. Content remains fluid, with no artificial center/max-width gap. Theme and AppShell changes are shared across Owner Web, so other screens inherit density changes but are not fully redesigned in this phase.

## Reference screens

- `NativeLocationsListPage.tsx`: semantic table, server-side search and pagination, metadata and occupancy, compact actions, responsive identity column, explicit source selection before opening the copy wizard. No implicit first-row copy.
- `ApiConfigurationLibraryPage.tsx`: compact shared resource table, resource-specific fields, exact prices, published/draft/archived state and version distinctions, accessible row menu. Below lg, collapse to identity/details plus actions columns; published templates retain visible Apply. The common renderer also affects asset/catalog, fee and policy lists. Existing editor, details, preview/confirmation and server contracts remain unchanged.
- `LocationWorkspaceOverview.tsx`, `LocationApiWorkspace.tsx`: compact header/tabs/KPIs, proportional room distribution strip, labeled status navigation, actual finance/occupancy, group confirmed zero follow-ups, preserve unknown and error states. Scope remains Location-specific, with owner finance visibility unchanged. Add Room opens editor through existing URL intent; no write on open.
- `PropertyApiPages.tsx`: supporting route-state regression correction for room-status filters and create intent. Pagination resets with scope/filter/search, consume create intent once, preserve authorization.
- `ApiConfigurationCopy.tsx`: optional compact header trigger with accessible label; existing copy logic unchanged.
