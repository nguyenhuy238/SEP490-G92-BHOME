# Main Contract: Two-party Sandbox confirmation

If the reviewed private PDF is missing, the document source first looks for an invitation copy with the exact original hash and length. Missing copies return a domain conflict instead of HTTP 500. Staff Sandbox simulation alone may then render a development PDF from the locked snapshot and record `RebuiltTestArtifact=true` plus `SandboxArtifactRebuiltFromLockedSnapshot`. This artifact is not the missing reviewed source or real signing evidence. Integrity mismatches still fail; real Owner/Tenant signing never uses this reconstruction.

Unsigned invitation history no longer hides Staff Sandbox actions. When Staff explicitly simulates Owner signing, existing unaccepted invitations are retained and revoked in the same transaction, with OTP/session hashes cleared and a distinct audit event. Any accepted invitation or real signing evidence still blocks conversion to simulation. Mobile refreshes Sandbox availability every five seconds while the contract remains open.

The development test workflow also permits assigned Staff to simulate Owner acceptance on Mobile through `POST /api/v1/contracts/{id}/internal-signing/owner-simulation`, with exact snapshot hash and explicit consent. This endpoint is Staff-only, checks the same Location Sandbox scope, rejects existing real invitations/evidence, and records `OwnerSimulatedBy` plus a distinct Staff simulation audit event. It does not grant Staff access to the real Owner-confirmation endpoint. After this simulation, Staff uses the existing Tenant-simulation endpoint; both persisted confirmations are required for QR.

This is a test workflow explicitly requested for the existing development sandbox. It does not create a Tenant account, OTP acceptance, CA signature or Tenant signing evidence.

Owner Web resolves the representative using `GET /api/v1/residents/{id}`. There is no account selector. Releasing a reviewed Main draft submits the account already linked to that verified Resident, or null for a new Resident. The backend continues to enforce the linkage.

For an unlinked Resident's Main contract using `INTERNAL_OTP_DRAWN`, the existing internal-signing status endpoint advertises `sandboxAvailable` only when the configured test scope permits the contract's Location. The scope requires Development/Testing, valid SePay Test configuration and either a disposable local test database or the explicitly configured Neon host/database/Location allowlist. Other Locations retain the real signing flow.

After releasing the draft, the Owner checks the test-consent checkbox and presses **Owner xác nhận ký (Sandbox)** in contract details. The existing `POST /api/v1/contracts/{id}/internal-signing/owner-confirmation` verifies the authenticated Owner, exact snapshot and consent. Contracts with existing invitations or signing evidence must finish their original flow.

Confirmation marks the contract as a development demo, stores `MainOwnerOnlySandboxV1` separately from real signing evidence and keeps the contract at PendingSigning. Assigned Staff must then press the Tenant simulation button on Mobile. `POST /api/v1/contracts/{id}/internal-signing/tenant-simulation` records the authenticated Staff and time before moving to PendingActivation. Owner confirmation alone never completes signing, including records created by the earlier Owner-only test flow. The original reviewed PDF is retained as an immutable test artifact. Repeated confirmation is idempotent. `ownerOnlySandboxConfirmed` reports the Owner confirmation; `sandboxTenantSimulated` separately reports the Staff simulation. Both are required before Mobile enables QR. These fields distinguish test outcomes from real Tenant signing.

Payment and activation recheck the Sandbox scope. A signature confirmation does not mark the deposit or rent paid. The QR still uses the existing initial-payment order and real test-provider reconciliation. Activation still verifies payment, document integrity and all other contract requirements. Do not enable this workflow in production or present its artifact as a legally signed contract.
