Ngày cập nhật: 06/11/2026.

## 1. Mục tiêu và nguồn yêu cầu

Phần triển khai bám theo SRS v1.3 trong `docs/reports/BHome_Report-3_Software Requirement Specification.docx`, đặc biệt UC-03, UC-05, UC-07..10, UC-18, UC-37..38; GBR-01..03, GBR-06, GBR-08, GBR-17, GBR-18 và DBR liên quan. Kiến trúc theo Report 4 được dùng làm tham chiếu, nhưng schema chạy thực tế là Compact24.

Các quyết định mới hơn đã được áp dụng:

- Bỏ Chain và RoomType. Room thuộc trực tiếp Location; giá/phí áp dụng theo Location hoặc Room.
- SRS sửa ngày 31/10 đã bỏ Staff Shift. UC-09 hiện là phân công Staff phụ trách Location. Dòng BE-09 cũ trong checklist còn ghi Shift nên không được dùng để tạo lại nghiệp vụ đã loại bỏ.
- Temporary residence do Tenant thực hiện bên ngoài BHOME. Tenant ghi trạng thái/bằng chứng, Owner xác nhận thông tin; Staff không được xử lý hoặc duyệt.
- Public Website chỉ đọc thông tin đã được Owner publish. Không có form liên hệ, booking, thanh toán hoặc thu thập dữ liệu Guest.
- Không tự đặt deadline/cadence cho JOB-08 khi báo cáo chưa chốt chính sách. API residence và thông báo theo sự kiện được tách khỏi quy tắc nhắc hạn còn tranh chấp.

## 2. Xác nhận database 24 bảng

Không tạo bảng mới, không thêm migration và không thêm cột trong đợt này. Toàn bộ phần mới dùng đúng các trường sẵn có trong Compact24:

| Phạm vi                  | Bảng/field Compact24                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| Profile và Staff account | `users`, `users.business_profile`, `users.history`                                         |
| Employment               | `staff_employments`; `employmentType` nằm trong `reward_penalty_policy` JSON               |
| Staff–Location           | `locations.staff_assignments`, `locations.history`, `locations.version`                    |
| Recurring task template  | `locations.operating_settings.recurringTaskTemplates`                                      |
| Task được sinh           | `operational_tasks` loại `GENERAL`, `source_key` chống tạo trùng                           |
| Residence                | `contract_residents.registration_*`, Owner confirmation và history                         |
| Occupancy/history        | projection từ `rooms`, `contracts`, `contract_residents`, `residents`                      |
| Public content           | `locations.public_profile`, `rooms.public_profile`, `published_at`, `published_by_user_id` |
| Ảnh private/public       | DB chỉ giữ object key/metadata; file nằm trong object storage private                      |
| Audit/inbox              | `notifications` với `record_kind` phù hợp                                                  |

Runtime đăng ký `Compact24DbContext` và repository mới đọc/ghi trực tiếp schema này. Tổng schema vẫn đúng 24 bảng như `docs/database/2026-11-03/compact-24/BHOME_24_TABLES.sql`.

## 3. API đã hoàn thiện

### BE-03 — UC-03: profile cá nhân

| Method | Endpoint                  | Mục tiêu                                                                                 |
| ------ | ------------------------- | ---------------------------------------------------------------------------------------- |
| GET    | `/api/v1/account/profile` | Xem Full Name, Phone, Email; Role và Account Status chỉ đọc                              |
| PUT    | `/api/v1/account/profile` | Cập nhật profile với optimistic version; đổi email hoặc số điện thoại thu hồi session cũ |
| POST   | `/api/v1/auth/login`      | Đăng nhập bằng đúng một định danh: `email` hoặc `phone` đã cập nhật trong profile        |

API chặn overposting bằng DTO strict và không cho client sửa role/trạng thái tài khoản. Số điện thoại được chuẩn hóa bằng cách bỏ khoảng trắng và các dấu phân cách thông dụng trước khi lưu/tìm kiếm; số đã thuộc tài khoản khác bị từ chối với HTTP 409. Đăng nhập email cũ vẫn tương thích. Không thêm bảng, cột hay migration cho thay đổi này vì dùng `users.phone` sẵn có.

### BE-05 — UC-05: Asset

Các API Asset CRUD hiện có được giữ nguyên. Bổ sung:

| Method | Endpoint                        | Mục tiêu                                                                        |
| ------ | ------------------------------- | ------------------------------------------------------------------------------- |
| PATCH  | `/api/v1/assets/{id}/condition` | Owner/Staff cập nhật riêng condition; Staff bị giới hạn theo Location được giao |

API dùng version, yêu cầu reason và không cho đường condition-only vượt qua Work Order đang mở hoặc Asset đã Retired.

### BE-07 — UC-07: occupancy và lịch sử Room

| Method | Endpoint                               | Mục tiêu                                                               |
| ------ | -------------------------------------- | ---------------------------------------------------------------------- |
| GET    | `/api/v1/occupancy`                    | Projection occupancy hiện tại, filter Location/Room status, phân trang |
| GET    | `/api/v1/rooms/{id}/occupancy-history` | Lịch sử hợp đồng và occupants của Room                                 |

Owner xem toàn hệ thống. Staff chỉ xem Location đang được giao theo trạng thái server hiện tại.

### BE-08 — UC-08: Staff account và employment

| Method | Endpoint             | Mục tiêu                                                |
| ------ | -------------------- | ------------------------------------------------------- |
| GET    | `/api/v1/staff`      | Danh sách Staff, search và filter active                |
| GET    | `/api/v1/staff/{id}` | Account + employment hiện hành                          |
| POST   | `/api/v1/staff`      | Tạo tài khoản Staff và employment trong một transaction |
| PUT    | `/api/v1/staff/{id}` | Cập nhật account/employment với version và reason       |

Chỉ Owner được gọi. Không cho deactivate Staff khi còn phân công hoặc task chưa giải quyết. Đổi email/deactivate cập nhật security stamp để token/session cũ không tiếp tục hợp lệ.

### BE-09 — UC-09 bản sửa 31/10: Staff–Location assignment

Hai API POST/GET hiện có vẫn dùng để tạo và xem date-range assignment. Bổ sung:

| Method | Endpoint                                          | Mục tiêu                      |
| ------ | ------------------------------------------------- | ----------------------------- |
| PUT    | `/api/v1/staff-location-assignments/{locationId}` | Thay Staff phụ trách hiện tại |
| DELETE | `/api/v1/staff-location-assignments/{locationId}` | Gỡ Staff phụ trách hiện tại   |

Thay/gỡ phân công yêu cầu `locationVersion`, `effectiveFrom` là ngày nghiệp vụ hiện tại và `reason`. Việc cập nhật `staff_assignments`, chuyển các task `GENERAL` chưa Completed/Cancelled và tạo inbox cho Staff cũ/mới diễn ra trong cùng transaction. Khi gỡ, task chưa hoàn tất trở về unassigned để Owner xử lý. Không tạo API Shift.

### BE-10 — UC-10: ad-hoc và recurring operational task

Ad-hoc task tiếp tục dùng `/api/v1/operational-tasks` và toàn bộ action/history/evidence hiện có. Bổ sung cấu hình recurring:

| Method | Endpoint                                                             | Mục tiêu                  |
| ------ | -------------------------------------------------------------------- | ------------------------- |
| GET    | `/api/v1/operational-task-templates?locationId=...`                  | Xem template của Location |
| POST   | `/api/v1/operational-task-templates`                                 | Tạo template              |
| PUT    | `/api/v1/operational-task-templates/{id}`                            | Cập nhật bằng version     |
| DELETE | `/api/v1/operational-task-templates/{id}?locationId=...&version=...` | Xóa template              |

Owner nhập rõ `intervalDays`, `nextRunAt` và `dueAfterHours`; backend không tự invent cadence. Background job `recurring-operational-tasks` dùng idempotency key theo phút, còn task dùng `source_key` theo template + kỳ chạy để không sinh trùng. Nếu Location chưa có Staff hợp lệ, task vẫn được tạo ở trạng thái unassigned.

### BE-18 — UC-18: temporary residence tracking

| Method | Endpoint                                                               | Quyền/mục tiêu                                   |
| ------ | ---------------------------------------------------------------------- | ------------------------------------------------ |
| GET    | `/api/v1/residence-tasks`                                              | Owner xem toàn hệ thống; Tenant chỉ xem bản thân |
| GET    | `/api/v1/residence-tasks/{contractId}/{residentId}`                    | Xem chi tiết và history trong scope              |
| PUT    | `/api/v1/residence-tasks/{contractId}/{residentId}`                    | Tenant ghi ngày thực tế, status và kết quả       |
| PUT    | `/api/v1/residence-tasks/{contractId}/{residentId}/evidence`           | Tenant upload ảnh private tối đa 5 MB            |
| GET    | `/api/v1/residence-tasks/{contractId}/{residentId}/evidence`           | Owner/Tenant hợp lệ tải evidence private         |
| POST   | `/api/v1/residence-tasks/{contractId}/{residentId}/owner-confirmation` | Owner xác nhận sau khi Completed + có evidence   |

Staff nhận 403. BHOME không gọi VNeID hay government API và không tuyên bố thay Tenant thực hiện đăng ký chính thức.

### BE-37 — UC-37: Owner publish public content

Cho cả Location và Room, Owner có các endpoint:

- `GET /api/v1/public-content/{locations|rooms}/{id}`
- `PUT /api/v1/public-content/{locations|rooms}/{id}`
- `POST /api/v1/public-content/{locations|rooms}/{id}/publish`
- `POST /api/v1/public-content/{locations|rooms}/{id}/unpublish`
- `PUT /api/v1/public-content/{locations|rooms}/{id}/photos`
- `DELETE /api/v1/public-content/{locations|rooms}/{id}/photos/{index}`

Ảnh được kiểm tra header/nội dung, giới hạn 5 MB và lưu private. Unpublish Location tự ẩn các Room con. Room chỉ publish khi Location cha active và đã publish.

### BE-38 — UC-38: anonymous read-only public API

| Method | Endpoint                                       |
| ------ | ---------------------------------------------- |
| GET    | `/api/v1/public/locations`                     |
| GET    | `/api/v1/public/locations/{id}`                |
| GET    | `/api/v1/public/locations/{id}/rooms`          |
| GET    | `/api/v1/public/rooms/{id}`                    |
| GET    | `/api/v1/public/locations/{id}/photos/{index}` |
| GET    | `/api/v1/public/rooms/{id}/photos/{index}`     |

Response là allowlist gồm mô tả, tiện ích, contact tĩnh được duyệt, giá tham khảo, vacancy và ảnh đã publish. Không trả Tenant, Staff, hợp đồng, hóa đơn hoặc dữ liệu identity.
