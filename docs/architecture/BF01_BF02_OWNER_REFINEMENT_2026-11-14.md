## Compatibility and data

Compact24 is the active persistence profile; prefer existing versioned JSON documents or nullable task state fields over new tables when adequate. Preserve original record IDs, audit and financial snapshot semantics. Legacy fields retained where needed by existing consumers. No destructive backfill: unknown historical unit is explicitly unknown until an authorized correction. New operational target data is nullable, so existing work remains whole-location. Configuration writes use version and scope checks, and retries must not duplicate operational writes.

## Implementation boundary

The UX examples and plan are not proof of runtime completion. Exact file changes, executed tests, limitations and migration status must be recorded in the implementation report. Existing development data and Mobile source are outside mutation scope.
